Reservoir Sampling for Streaming Data

난이도 / Difficulty: Intermediate
날짜 / Date: 2026-10-07

내용

Reservoir 샘플링은 무한히 도착하는 스트림에서 고정 크기(k)의 균일 샘플을 유지하는 알고리즘으로, 로그/메트릭/트레이스의 저장·분석 비용을 낮추면서 전체 분포를 보존합니다.

핵심 아이디어는 단일 패스(single-pass)와 O(k) 메모리만으로 첫 k개는 그대로 저장하고 이후 i번째 아이템은 확률 k/i로 대체 여부를 결정하는 Vitter의 Algorithm R(1985)입니다. 가중치 샘플링(예: 이벤트 우선순위가 다를 때)은 Efraimidis-Spirakis(2006) 방식처럼 각 항목에 무작위 키를 부여하고 상위 k개를 유지하는 방법으로 구현합니다.
실무 관점에서는 스트림 처리 프레임워크(예: Kafka consumer, Flink operator, Beam DoFn) 안에서 상태(stateful)로 유지하거나, 경량 에이전트에서 텔레메트리 샘플을 선행 필터링할 때 사용합니다. 복잡도는 항목당 O(1) 확률 검사(균등 샘플) 또는 O(log k) 힙 조작(가중 샘플)이며, 분산 환경에서는 각 파티션별로 샘플을 유지한 뒤 합치는 패턴을 씁니다.

활용

실제 사용 사례 및 코드(파이썬):
- 이론/참고: Vitter, 1985; Efraimidis & Spirakis, 2006
- 오픈소스: AddThis stream-lib의 ReservoirSampler(java)
- Kafka 소비자 통합 예:

python 코드 스니펫:

import random
k=100
reservoir=[]
count=0
for item in kafka_consumer():
count+=1
if count<=k: reservoir.append(item)
else:
j = random.randint(1,count)
if j<=k: reservoir[j-1]=item
# reservoir는 균일 샘플

가중치 샘플(스트림, 상위-k 유지):

import heapq, random, math
k=50
heap=[]
for item, w in stream():
key = -math.log(random.random())/w
if len(heap) elif key>heap[0][0]: heapq.heapreplace(heap,(key,item))

베스트 프랙티스: 파티셔닝 별 샘플 유지 후 합치기, 체크포인트 가능한 상태 저장, 타임윈도우별 샘플링으로 장기 편향 회피.

Content

Reservoir sampling maintains a fixed-size (k) uniform sample from an unbounded stream in a single pass using O(k) memory — ideal for telemetry/log sampling and online analytics.

The core is Vitter’s Algorithm R (1985): keep the first k items, then for the i-th item (i>k) pick it with probability k/i and replace a random existing element if selected. For weighted priorities, use Efraimidis-Spirakis (2006): assign each item a random key derived from its weight and keep the top-k keys (can be implemented with a min-heap).
In production this runs inside stream processors (Kafka consumer loops, Flink stateful operators, Beam DoFns) or on-edge agents to reduce ingestion costs while preserving distributional properties. Complexity is O(1) per item for uniform sampling and O(log k) for weighted sampling (heap ops). In distributed setups, keep per-partition reservoirs and merge (e.g., sample union with proportional down-sampling) to avoid coordination bottlenecks.

Applications

Real-world sources: Vitter (1985), Efraimidis & Spirakis (2006), open-source AddThis stream-lib (Java) ReservoirSampler. Example integrations:

Python uniform reservoir (Kafka-like loop):

import random
k=100
reservoir=[]
count=0
for item in kafka_consumer():
count+=1
if count<=k: reservoir.append(item)
else:
j = random.randint(1,count)
if j<=k: reservoir[j-1]=item

Weighted streaming top-k (heap):

import heapq, random, math
k=50
heap=[]
for item, weight in stream():
key = -math.log(random.random())/weight
if len(heap) elif key>heap[0][0]: heapq.heapreplace(heap,(key,item))

Production tips: checkpoint reservoir state for recovery, maintain per-partition reservoirs and merge offline, use time-windowed reservoirs to keep samples fresh for concept-drift-sensitive applications.
