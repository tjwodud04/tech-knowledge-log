Word Sense Disambiguation (WSD)

난이도 / Difficulty: Intermediate
날짜 / Date: 2026-10-02

내용

단어 의미 중복을 문맥 기반으로 식별하는 기술로, 검색·번역·대화시스템에서 올바른 의미 선택이 결과 품질을 좌우합니다.

WSD는 같은 형태의 단어가 가지는 여러 의미 중 문맥에 맞는 것을 고르는 문제입니다. 전통적 접근은 Lesk 알고리즘(문맥과 정의의 겹침을 계산)이나 지식 기반 그래프(WordNet/BabelNet, UKB)였고, 지도학습은 SemCor 같은 라벨 데이터로 SVM/CRF를 학습했습니다. 최근에는 문맥 표현을 제공하는 ELMo/BERT 계열의 임베딩으로 문장-의미(글로스) 간 유사도를 계산하거나, gloss-aware fine-tuning(GlossBERT)으로 높은 성능을 냅니다 (Raganato et al., 2017; Huang et al., GlossBERT).

실무에서는 사전(WordNet/BabelNet)으로 후보 sense를 얻고, 후보 글로스나 예문을 임베딩해 문맥 임베딩과 코사인 유사도로 점수화하는 패턴이 널리 쓰입니다. 대규모 시스템은 후보 임베딩 캐싱, 배치 점수화, 백오프(품사 고정/빈도 기반) 전략을 병행해 레이턴시와 정밀도 균형을 맞춥니다. 주요 적용처는 검색 쿼리 이해, 기계번역, 음성비서의 슬롯 해석 등입니다.

활용

실제 예: HuggingFace BERT와 NLTK WordNet을 이용한 간단한 WSD(문맥-글로스 유사도 방식).

코드(요약):
from transformers import AutoTokenizer, AutoModel
import torch
from nltk.corpus import wordnet as wn

tok=AutoTokenizer.from_pretrained('bert-base-uncased')
model=AutoModel.from_pretrained('bert-base-uncased')

def embed(text):
i=tok(text,return_tensors='pt')
o=model(**i).last_hidden_state.mean(1)
return o.detach()

context='I deposited money at the bank.'
for s in wn.synsets('bank'):
score=torch.cosine_similarity(embed(context), embed(s.definition()))
print(s.name(), float(score))

생산 환경 팁: 후보 임베딩은 미리 계산·캐시하고(특히 BabelNet/WordNet 글로스), 배치 유사도 계산을 GPU에서 처리, 낮은 신뢰도 시 빈도 기반 후보로 백오프. 오픈소스/참고: UKB(Agirre), Babelfy(BabelNet), Raganato et al. (2017) 평가 프레임워크.

Content

WSD chooses the intended sense of an ambiguous word given context; it's critical for search, MT, and conversational agents to avoid incorrect interpretations.

Word Sense Disambiguation picks one sense among many for a surface form using its context. Classical methods include Lesk (overlap with dictionary glosses) and graph-based knowledge methods (WordNet/BabelNet with UKB). Supervised approaches used SVMs/CRFs with SemCor-labeled data. The recent dominant paradigm uses contextual embeddings (ELMo/BERT) to represent the sentence and either score glosses or fine-tune sense-aware classifiers (e.g., GlossBERT), which substantially improved benchmarks (Raganato et al., 2017).

In production, practitioners typically: 1) retrieve candidate senses from a lexical resource (WordNet/BabelNet), 2) compute embeddings for the context and for each candidate gloss or example, 3) pick the highest-similarity sense, with caching and batch GPU scoring to meet latency. Systems fall back to POS or frequency priors when confidence is low. Applications include query understanding in search, disambiguation for MT preprocessing, and slot interpretation in voice assistants.

Applications

Real code example (context-gloss scoring with HuggingFace + NLTK WordNet):

from transformers import AutoTokenizer, AutoModel
import torch
from nltk.corpus import wordnet as wn

tok=AutoTokenizer.from_pretrained('bert-base-uncased')
model=AutoModel.from_pretrained('bert-base-uncased')

def embed(text):
i=tok(text,return_tensors='pt')
o=model(**i).last_hidden_state.mean(1)
return o.detach()

context='I deposited money at the bank.'
for s in wn.synsets('bank'):
score=torch.cosine_similarity(embed(context), embed(s.definition()))
print(s.name(), float(score))

Production patterns/best practices: precompute and cache gloss embeddings (WordNet/BabelNet), batch GPU similarity computations, use priors/backoff for low-confidence cases, and evaluate with standardized datasets (Senseval/WSD benchmarks; see Raganato et al., 2017). Industry note: major tech stacks use contextual embeddings for disambiguation in query understanding and MT (Google, Microsoft, Amazon) and open-source tools like UKB/Babelfy and BabelNet are common resources.
