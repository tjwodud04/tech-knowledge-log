Suffix Arrays & Suffix-Array-Based String Search

난이도 / Difficulty: Intermediate
날짜 / Date: 2026-10-05

내용

접미사 배열(suffix array)은 텍스트의 모든 접미사를 사전순으로 정렬한 정수 배열로, 메모리 효율적인 전역 부분문자열 검색과 압축 인덱스(FM-index)의 기반이 됩니다. 실무에서는 대용량 문자열 인덱싱(유전체 서열 정렬, 텍스트 검색 엔진의 압축 인덱스 등)에 자주 쓰입니다.

작동 원리는 간단합니다: 길이 n 문자열 S에 대해 모든 접미사 S[i:]의 시작 인덱스들을 사전순으로 정렬하여 SA를 만듭니다. 패턴 P의 출현은 SA 위에서 이분 탐색(binary search)으로 O(m log n) 시간(여기서 m은 패턴 길이)으로 찾을 수 있고, LCP(Longest Common Prefix) 배열을 추가하면 이분 탐색 시 비교 비용을 줄여 실전 성능을 크게 개선합니다. 접미사 배열 구성 알고리즘으로는 SA-IS(O(n))나 divsufsort(실무에서 널리 쓰이는 고속 구현)가 널리 사용됩니다.

실제 대규모 텍스트(예: 게놈 서열, 로그 아카이브)에는 SA를 직접 저장하면 메모리 부담이 크므로 BWT(버로우스-웨일러 변환)와 샘플링 기반의 FM-index처럼 SA를 압축·샘플링한 구조를 씁니다. 예컨대 BWA와 Bowtie(유전체 정렬기)는 SA→BWT→FM-index 체인을 사용해 짧은 리드(시퀀스)를 고속으로 정렬합니다. 오픈소스 구현체로는 libdivsufsort(접미사 배열 빌더), SDSL(sdsl-lite)의 압축 색인, sais 등이 있습니다.

실무 패턴/베스트프랙티스:
- 큰 데이터는 압축 색인(FM-index, Wavelet Tree) 사용. sdsl-lite 추천.
- SA 빌드는 메모리/병렬화 고려: libdivsufsort는 빠르지만 대용량은 외부 메모리 알고리즘이나 샘플링 필요.
- LCP, RMQ를 함께 사용해 다중매칭과 빈도쿼리를 가속.

Content

A suffix array (SA) is an array of start positions of all suffixes of a string sorted lexicographically; it’s a compact foundation for fast substring queries and the FM-index used in production systems for compressed full-text search and bioinformatics.

How it works: for a text S of length n, SA stores indices i such that S[i:] are sorted. You can find occurrences of a pattern P by binary searching SA — naive cost is O(m log n) for a pattern of length m. Adding an LCP (Longest Common Prefix) array and using range minimum queries reduces character comparisons and speeds up repeated or batched queries. Construction algorithms include SA-IS (linear time) and practical high-speed implementations like divsufsort.

In production you rarely keep a full SA for large corpora because of memory. Instead SA → BWT → FM-index (sampled SA + rank/select structures like wavelet trees) yields a compressed index that supports fast locate/count operations with low RAM. This pipeline is central to read aligners (BWA, Bowtie) and appears in compression/search libraries (sdsl-lite, libdivsufsort).

Best practices:
- For large texts use sampled SA + FM-index to trade time for RAM.
- Use LCP+RMQ to speed many queries.
- Use well-tested libraries (libdivsufsort, sdsl) rather than ad-hoc SA builders in production.
