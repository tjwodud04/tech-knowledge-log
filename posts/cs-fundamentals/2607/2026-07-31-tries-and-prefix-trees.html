Tries & Prefix Trees (Patricia / Radix / FST)

난이도 / Difficulty: Intermediate
날짜 / Date: 2026-07-31

내용

트라이(Trie)는 문자열의 접두(prefix)를 노드로 표현해 빠른 접두 검색, 자동완성, longest-prefix-match에 특화된 자료구조로서 실무 시스템에서 색인·라우팅·사전 압축에 널리 쓰입니다.

작동 원리: 트라이는 각 문자(혹은 문자 블록)를 간선으로 하는 트리로, 공통 접두를 공유해 메모리를 절약하고 접두 검색을 O(L) (L=키 길이)로 수행합니다. 실무에선 메모리/속도 균형을 위해 경계 병합(radix/compacted trie), 비트 기준 분기(Patricia) 또는 상태 기계(FST)를 씁니다. FST(유한상태전이기계)는 동일한 출력(또는 가중치)을 공유 가능한 경로로 압축해 대규모 단어 사전(역색인 사전, 자동완성)에서 메모리와 I/O를 줄입니다.

알고리즘 포인트: 삽입/탐색은 트리 탐색이며, 삭제는 자식 노드 유무에 따라 경계 병합을 수행합니다. Patricia/radix는 길이가 긴 일찍 갈라지는 경로를 하나의 엣지로 병합해 포인터 수와 캐시 미스를 줄입니다. FST는 정렬된 키 목록으로 최소 유한상태 기계를 구성하므로 읽기 전용 대규모 사전에 적합합니다. 성능 튜닝은 문자 집합(UTF-8 블록), 노드 레이아웃(배열 vs 해시), 레벨별 압축을 고려합니다.

활용

실제 사용 사례 및 코드:
- Lucene FST: 검색엔진에서 용어 사전과 자동완성(autocomplete)에 사용. (Apache Lucene)
Java 예시 (간단):
java.nio.charset.Charset cs = java.nio.charset.StandardCharsets.UTF_8;
org.apache.lucene.util.fst.Builder b = new org.apache.lucene.util.fst.Builder<>(org.apache.lucene.util.fst.FST.INPUT_TYPE.BYTE1, org.apache.lucene.util.fst.NoOutputs.getSingleton());
// 정렬된 키들을 바이트 배열로 feed해서 FST 생성

- ripgrep / fst crate (Rust, BurntSushi): 대용량 문자열 매칭과 자동완성 색인에 사용됩니다.
Rust 예시:
use fst::Map; let keys = vec!["apple","app","banana"]; let wtr = fst::Map::from_iter(keys.into_iter().enumerate().map(|(i,k)|(k.as_bytes(), i))).unwrap();

- 네트워크 라우팅: BGP/OSPF 라우터(FRRouting/Cisco)는 longest-prefix-match를 위해 Patricia/radix 트리를 사용합니다(실제 라우팅 테이블 구현).

베스트프랙티스: 읽기 전용 대규모 사전엔 FST, 동적 삽입·삭제엔 radix/patricia, 메모리 제약이 강할 땐 MARISA-trie 같은 압축 구현을 사용하세요.

Content

A trie (prefix tree) stores keys by shared prefixes enabling O(L) prefix lookup and efficient auto-complete, longest-prefix match, and dictionary compression—widely used in search engines, routing stacks, and NLP indexing.

How it works: A trie represents each character (or block) as an edge and each prefix as a node; shared prefixes collapse common paths. Practical systems use compacted/radix tries (merge single-child paths), Patricia tries (bitwise branching for IP prefixes), or FSTs (finite-state transducers) that merge equivalent suffixes/outputs for extreme memory efficiency. Insert/search run in time proportional to key length; deletions require potential edge/node compression.

Technical notes: Choose node layout (array for small alphabets, hash/map for sparse alphabets), block/byte granularity for UTF-8, and compressed representations to reduce pointer overhead. FSTs are built from sorted key lists and produce minimized automata ideal for read-heavy workloads (Lucene, Rust fst crate). Patricia/radix implementations optimize for longest-prefix-match in routing by storing bits/prefix-lens on edges.
