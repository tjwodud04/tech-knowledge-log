TF–IDF & Bag-of-Words (BoW)

난이도 / Difficulty: Intermediate
날짜 / Date: 2026-09-09

내용

Bag-of-Words는 문서를 단어 빈도 벡터로 변환하는 단순 표현이고, TF–IDF는 단어의 문서 내 중요도를 빈도와 역문서빈도(idf)로 조정해 실무에서 강력한 특징(feature)으로 쓰입니다.

작동 원리: BoW는 토큰화→어휘집 구축→단어 카운트(또는 n-그램) 순으로 진행합니다. TF–IDF는 각 단어 t에 대해 TF(t,d)=raw count 또는 sublinear scale(1+log tf) 형태를 쓰고, IDF(t)=log((N+1)/(df(t)+1))+1 같은 smooth 공식으로 자주 보정합니다. 최종 특징은 TF×IDF에 L2 정규화가 흔합니다. 실무적 고려사항으로는 불용어 제거, 어간 추출/표제어화, n-그램, 희소성 때문에 희소 행렬(scipy.sparse) 사용이 필수입니다.

시스템 적용: 검색엔진(Lucene/Elasticsearch의 "classic" similarity는 TF–IDF 기반이고, 최신 기본값은 BM25)과 문서 분류, 추천 및 피처 엔지니어링 파이프라인에서 널리 사용됩니다. 대용량 스트리밍 환경에서는 HashingVectorizer로 차원 고정 후 TfidfTransformer를 적용해 온라인 처리합니다. 학술적으로는 Sparck Jones의 IDF 개념과 Salton의 Vector Space Model이 근간입니다.

활용

실제 코드(파이썬, scikit-learn):

from sklearn.feature_extraction.text import TfidfVectorizer
corpus = ["buy cheap laptop", "discount on laptop", "laptop review"]
vec = TfidfVectorizer(ngram_range=(1,2), max_df=0.8, min_df=1, sublinear_tf=True)
X = vec.fit_transform(corpus) # scipy.sparse matrix

대규모/스트리밍: HashingVectorizer + TfidfTransformer
from sklearn.feature_extraction.text import HashingVectorizer, TfidfTransformer
hv = HashingVectorizer(n_features=2**20, alternate_sign=False)
X_stream = hv.transform(batch)
X_tfidf = TfidfTransformer(norm='l2', use_idf=True, smooth_idf=True).fit_transform(X_stream)

실무 적용 예: Lucene/Solr/Elasticsearch(검색 랭킹·피처); scikit-learn/gensim(분류·토픽 전처리); 연구 예로 BM25 vs TF–IDF 비교 논문들(정보검색 교재와 수많은 엔지니어링 블로그). 베스트 프랙티스: sublinear TF, idf smoothing, L2 정규화, 희소 행렬 사용, 온라인엔 해싱으로 메모리 고정.

Content

Bag-of-Words (BoW) turns documents into count vectors; TF–IDF weights those counts by inverse document frequency to emphasize discriminative words—widely used as practical features in production search, classification, and recommendation systems.

How it works: BoW pipeline = tokenize → build vocabulary → count tokens (optionally n-grams). TF–IDF computes TF (raw count or sublinear: 1+log(tf)) and IDF (smoothed: log((N+1)/(df+1))+1) then multiplies and usually L2-normalizes. Implementation details matter: stopword lists, stemming/lemmatization, n-grams, and sparse matrix formats (scipy.sparse) to handle high dimensionality. TF–IDF is interpretable and fast, but static IDF can be stale in streaming; for that use hashing and approximate document-frequency strategies.

Where used: classic IR systems (Lucene historically used TF–IDF; Elasticsearch exposes a "classic" similarity), but modern search often prefers BM25. TF–IDF remains popular for ML pipelines (feature vectors for classifiers), e-mail/news deduplication, and as baseline features in recommendation systems. Academic roots trace to Sparck Jones (IDF) and Salton (vector space model).

Applications

Practical code (scikit-learn):

from sklearn.feature_extraction.text import TfidfVectorizer
corpus = ["buy cheap laptop", "discount on laptop", "laptop review"]
vec = TfidfVectorizer(ngram_range=(1,2), max_df=0.8, min_df=1, sublinear_tf=True)
X = vec.fit_transform(corpus) # sparse matrix for ML models

Streaming/large-scale pattern (fixed memory):
from sklearn.feature_extraction.text import HashingVectorizer, TfidfTransformer
hv = HashingVectorizer(n_features=2**20, alternate_sign=False)
X_batch = hv.transform(batch)
X_tfidf = TfidfTransformer(norm='l2', use_idf=True, smooth_idf=True).fit_transform(X_batch)

Real deployments: Apache Lucene/Solr and Elasticsearch (search ranking; Lucene switched default to BM25 but TF–IDF "classic" is available), gensim and scikit-learn (feature engineering in production ML), and many research comparisons (TF–IDF baseline vs neural embeddings). Best practices: use sublinear TF, idf smoothing, L2 normalization, sparse storage, and hashing for streaming ingestion.
