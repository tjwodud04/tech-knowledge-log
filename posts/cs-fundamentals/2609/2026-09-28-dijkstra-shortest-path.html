Dijkstra's Shortest-Path Algorithm

난이도 / Difficulty: Intermediate
날짜 / Date: 2026-09-28

내용

Dijkstra 알고리즘은 가중치가 비음수인 그래프에서 단일 출발점 최단 경로를 찾는 고전 알고리즘으로, 라우팅·맵핑·네트워크 제어 등 실무 시스템의 기초로 쓰입니다.

작동 원리: 시작 정점에서부터 각 정점까지의 현재 최단 거리 추정치를 유지하고, 우선순위 큐(보통 최소 힙)로 최단 추정치가 가장 작은 정점을 반복적으로 확정한다. 간단한 구현은 O((V+E) log V) 시간 복잡도를 가지며, 다익스트라 자체는 음수 간선을 허용하지 않는다. 실무에서는 기본 다익스트라를 그대로 쓰기보다 Contraction Hierarchies(Geisberger 등)나 ALT, PHAST 같은 가속 기법과 결합하여 대규모 도로망 또는 실시간 서비스에서 성능을 확보한다.

시스템 적용: OSPF(인터넷 라우팅 프로토콜)는 링크 상태 데이터베이스를 만들고 라우팅 테이블 계산에 Dijkstra를 사용한다. 지도/네비게이션 엔진(GraphHopper, OSRM, GraphHopper는 내부 전처리 후 쿼리에서 다익스트라 기반 탐색을 사용)과 연구(Contraction Hierarchies, Transit Node Routing)에서도 핵심으로 활용된다.

활용

실제 코드(파이썬, NetworkX와 간단 구현):

# heapq 기반 최소 경로
import heapq
def dijkstra(adj, src):
dist = {src:0}
pq = [(0, src)]
while pq:
d,u = heapq.heappop(pq)
if d>dist[u]: continue
for v,w in adj.get(u,[]):
nd = d + w
if nd < dist.get(v, 10**18):
dist[v]=nd
heapq.heappush(pq,(nd,v))
return dist

# NetworkX 사용 예
import networkx as nx
G = nx.DiGraph()
G.add_weighted_edges_from([(1,2,7),(1,3,2),(3,2,1)])
print(nx.single_source_dijkstra_path_length(G,1))

실무 팁: 대규모 정적 도로망은 전처리(축소, 터널링)로 쿼리 속도를 수백 배 개선. 빈번한 업데이트(실시간 교통)는 동적 기법과 히트-캐시(지역 재탐색) 병행. 출처: OSPF RFC, GraphHopper(오픈소스), Geisberger et al. Contraction Hierarchies.

Content

Dijkstra's algorithm finds shortest paths from a single source on non‑negative weighted graphs; it's a foundational building block in routing, mapping, and network control systems.

How it works: maintain tentative distances from the source and repeatedly settle the closest unsettled vertex using a min-priority queue (min-heap). Relax outgoing edges to update neighbors. Complexity with a binary heap is O((V+E) log V). Dijkstra forbids negative weights; in production you often combine it with acceleration techniques (Contraction Hierarchies, ALT, PHAST) to handle large road networks and low-latency queries.

Where used: OSPF uses Dijkstra to compute routing tables from link-state databases. Map services and routing engines (GraphHopper, OSRM) use Dijkstra-derived searches during queries or in preprocessing stages. Research on fast shortest-path queries (Geisberger et al., 2008) extends Dijkstra with contraction to achieve interactive latencies on continental graphs.

Production patterns & best practices: for static large graphs use preprocessing (Contraction Hierarchies, Transit Nodes) to reduce query time; for frequently changing weights use localized re-search or incremental algorithms.
