Byte-Pair Encoding (BPE)

난이도 / Difficulty: Intermediate
날짜 / Date: 2026-08-12

내용

BPE는 텍스트를 바이트/문자 단위에서 빈도 기반으로 병합해 어휘를 만드는 서브워드 기법으로, 희귀단어 처리와 모델 크기/성능 균형에 중요합니다.

작동 원리: 초기에는 모든 문자를 토큰으로 보고, 훈련 코퍼스에서 가장 자주 등장하는 인접 토큰 쌍을 반복적으로 병합합니다. 각 병합은 새로운 토큰(서브워드)을 만들고 어휘집에 추가됩니다. Sennrich et al. (2015) 논문에서 기계번역에 BPE를 적용해 OOV 문제를 줄였고, GPT-2(오픈AI)는 바이트-레벨 BPE를 사용해 바이너리 안정성과 멀티언어 지원을 확보했습니다. 기술적 포인트: 병합 빈도 계산과 반복 횟수(어휘 크기), 바이트-레벨 처리 여부(UTF-8 안전성), 디코딩 시 longest-match 규칙(그리디 매칭)이 실전에서 중요합니다.

성능·운영: 대규모 파이프라인에서는 Tokenizer 훈련을 병렬화하고(예: Hugging Face tokenizers의 Rust 구현), 훈련된 merges 파일과 vocab 파일을 모델 버전과 함께 저장/배포합니다. 체크포인트 간 호환성 유지와 토크나이저 재현성(reproducibility)이 실무 관건입니다.

활용

실무 예시 — Hugging Face tokenizers(토크나이저 훈련 및 사용):

Python 예제 (byte-level BPE):
from tokenizers import ByteLevelBPETokenizer
# 학습: 데이터는 줄 단위 텍스트 파일
tokenizer = ByteLevelBPETokenizer()
tokenizer.train(files=["data.txt"], vocab_size=30000, min_frequency=2)
tokenizer.save_model("./tokenizer")
# 인코딩
ids = tokenizer.encode("Hello, world!").ids
print(ids)

참고: GPT-2(바이트-레벨 BPE) 구현: Radford et al., OpenAI GPT-2(2019). WordPiece/SentencePiece(구글)는 변형으로, SentencePiece는 바이너리 세그먼트와 unigram 모델도 제공합니다. 실무 베스트프랙티스: 토크나이저 버전 고정, merges + vocab 함께 배포, 훈련 데이터 도메인(특수 토큰/도메인 어휘) 반영.

Content

BPE is a subword tokenization method that iteratively merges frequent adjacent byte/character pairs to build a compact vocabulary, crucial for handling rare words and controlling model size in production.

How it works: Start with characters (or bytes) as atomic tokens and count adjacent token pair frequencies across the corpus. Repeatedly merge the highest-frequency pair into a new token until reaching a target vocab size. Key engineering choices: using bytes vs. Unicode characters (byte-level BPE avoids unknown bytes and preserves reversible tokenization), deciding vocab_size and min_frequency, and applying greedy longest-match decoding. Sennrich et al. (2015) demonstrated BPE's effectiveness for neural machine translation; GPT-2 uses a byte-level BPE variant to ensure byte-level safety and cross-lingual capability.

Operational notes: Use optimized libraries (Hugging Face tokenizers in Rust) for speed, persist vocab+merges files with model checkpoints, and lock tokenizer config in production to ensure reproducible tokenization.

Applications

Real-world code (Hugging Face tokenizers):
from tokenizers import ByteLevelBPETokenizer
# Train on newline-separated corpus
tokenizer = ByteLevelBPETokenizer()
tokenizer.train(files=["data.txt"], vocab_size=50000, min_frequency=2)
tokenizer.save_model("./tokenizer")
# Use
print(tokenizer.encode("Hello, world!").tokens)

Other productions: OpenAI GPT-2 uses byte-level BPE (Radford et al., 2019); Google uses WordPiece/SentencePiece for BERT/Translation (SentencePiece also supports BPE and unigram). Best practices: co-deploy vocab+merges with model, fix tokenizer version in serving, and tune vocab_size to balance OOV vs. tokenizer length. See: Sennrich et al. 2015, Hugging Face tokenizers repo, Google SentencePiece.
